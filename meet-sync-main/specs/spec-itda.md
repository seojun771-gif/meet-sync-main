# 잇다(ITDA) - 팀 매칭 및 완주 신뢰 서비스 MVP

## 문제

대학생은 공모전, 조별과제, 동아리·스터디 프로젝트를 시작할 때 지도교수·선후배 인맥으로 팀을 못 구하면 에브리타임 게시판, 카카오톡 오픈채팅방을 전전하며 팀원을 구한다. 이렇게 구성된 팀은 팀원의 실제 협업 태도(끝까지 완주하는지, 무임승차·잠수를 하는지)를 사전에 알 수 없고, 프로젝트가 끝난 뒤에도 그 결과가 어디에도 기록되지 않아 다음 팀 구성 때 같은 문제를 반복한다.

## 해결

대학생이 프로필 기반으로 신뢰할 수 있는 팀원을 찾고, 프로젝트가 끝난 뒤에는 완주 여부와 동료 평가가 자동으로 기록되어 "완주율"이라는 눈에 보이는 신뢰 지표로 쌓인다. 팀원들은 팀 스페이스 안에서 프로젝트를 진행하고, 마감이 되면 완주 여부가 판정되어 각자의 Trust Score에 반영된다.

## 사용자 스토리

1. 팀원을 구하는 대학생으로서, 나는 프로필을 등록하고 싶다. 그래야 다른 사람이 나를 신뢰할 근거(과거 완주율, Trust Score)를 보고 팀에 초대할 수 있다.
2. 팀을 꾸리는 대학생으로서, 나는 팀 스페이스를 만들고 팀원을 초대하고 싶다. 그래야 프로젝트를 시작할 수 있다.
3. 초대받은 대학생으로서, 나는 초대를 수락하거나 거절하고 싶다. 그래야 원치 않는 팀에 억지로 들어가지 않는다.
4. 팀원으로서, 나는 팀 스페이스 목록에서 내가 참여 중인 프로젝트를 한눈에 보고 싶다. 그래야 여러 프로젝트를 동시에 진행해도 헷갈리지 않는다.
5. 팀원으로서, 나는 프로젝트 마감일이 되면 완주 여부를 확인(동의)하고 싶다. 그래야 내 완주 이력이 정확하게 기록된다.
6. 팀원으로서, 마감 후 7일 안에 완주 확인을 하지 않아도 시스템이 자동으로 완주 처리해주길 원한다. 그래야 한 사람의 무응답 때문에 팀 전체 기록이 영원히 미확정 상태로 남지 않는다.
7. 팀원으로서, 나는 프로젝트가 완주 처리된 뒤 동료를 평가하고 싶다. 그래야 실제 협업 태도가 다음 팀 구성에 참고 자료로 남는다.
8. 팀원으로서, 나는 팀원 전원이 평가를 제출하기 전에는 다른 사람의 점수를 볼 수 없어야 한다. 그래야 보복성으로 낮은 점수를 주고받는 담합이 일어나지 않는다.
9. 팀원으로서, 나는 내 Trust Score와 완주율을 프로필에서 확인하고 싶다. 그래야 다음 팀원 모집 때 내 신뢰도를 증명할 수 있다.
10. 신규 사용자로서, 나는 평가 횟수가 3회 미만이면 확정 점수 대신 "집계 중" 배지를 보고 싶다. 그래야 몇 번 안 해본 상태에서 낮은 점수 하나로 낙인찍히지 않는다.

## 정한 것

- 완주 판정: 팀원 전원이 "완료" 확인을 하면 완주로 기록된다. 마감일로부터 7일 안에 전원 확인이 안 되면 시스템이 자동으로 완주 처리한다.
- 상호평가: 완주 처리된 프로젝트에 한해 팀원 전원이 참여하며, 전원이 제출하기 전까지는 서로의 점수·코멘트를 볼 수 없는 블라인드 방식이다.
- Trust Score 잠정 가중치: 완주율 40%, 마감 준수율 25%, 동료 평가 평균 25%, 최근 활동 보정 10%. 진행 예정인 대학생 100명 설문 결과에 따라 조정한다.
- 평가 횟수 3회 미만인 사용자는 확정 점수 대신 "집계 중" 배지로 노출한다.
- 이번 MVP는 공모전·조별과제·동아리 세 상황을 모두 잠재 대상으로 하되, 화면과 기능은 시나리오 구분 없는 공통 플로우로 만든다. 첫 타겟 시나리오와 시나리오별 차이는 진행 중인 설문 결과로 이후에 결정한다.
- 화면 구성은 최소 3개다 — ① 팀 스페이스 목록, ② 팀 스페이스 상세(완주 판정 + 상호평가), ③ 내 프로필(Trust Score·완주율 표시).

## 만들지 않을 것

- 공모전·조별과제·동아리 시나리오별 UX 분기 (설문 결과가 나오기 전까지는 공통 플로우만 사용)
- 외부 검증 신호 하이브리드 결합 (GitHub 커밋 이력, 공모전 수상 기록 연동 등, Phase 2~3 대상)
- 완주 이력을 활용한 채용 연계 기능 (Phase 3 대상)
- 평가자 신뢰가중치 자동 계산, 담합 패턴 자동 탐지, 베이지안 스무딩, 시간 가중 감쇠 등 통계적 보정 로직 (설문으로 초기 가중치가 확정된 이후 별도 검토)
- Trust Score 산출 공식·가중치의 최종 확정 (100명 설문 결과가 나온 뒤 별도로 다룬다)

## 확인 방법

- **Given** 팀 스페이스를 만들지 않은 상태에서 / **When** 팀원을 초대하고 상대가 수락하면 / **Then** 팀 스페이스 목록에 새 프로젝트가 보인다
- **Given** 프로젝트 마감일이 지난 상태에서 / **When** 팀원 전원이 완료 확인을 누르면 / **Then** 해당 프로젝트가 "완주"로 표시되고 상호평가 화면이 열린다
- **Given** 프로젝트 마감일이 지났지만 팀원 중 일부가 완료 확인을 하지 않은 상태에서 / **When** 마감일로부터 7일이 지나면 / **Then** 시스템이 자동으로 "완주"로 확정 처리한다
- **Given** 완주 처리된 프로젝트에서 팀원 일부만 평가를 제출한 상태에서 / **When** 아직 전원이 제출하지 않았으면 / **Then** 제출한 팀원도 다른 사람의 점수·코멘트를 볼 수 없다
- **Given** 평가 횟수가 2회뿐인 사용자의 프로필을 볼 때 / **When** Trust Score를 확인하면 / **Then** 확정 숫자 대신 "집계 중" 배지가 보인다
- **Given** 평가 횟수가 3회 이상 쌓인 사용자의 프로필을 볼 때 / **When** Trust Score를 확인하면 / **Then** 완주율 40%·마감준수율 25%·동료평가 25%·최근활동 10% 가중치로 계산된 확정 점수가 보인다
